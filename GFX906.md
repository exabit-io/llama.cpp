# llama.cpp for gfx906 (Radeon Pro Vega II / MI50 class, wave64, no MFMA)

This repository is a gfx906-only llama.cpp: upstream master plus everything known to make the four-die Vega 20 boxes fast,
maintained for a fleet of 2019 Mac Pro nodes with four gfx906 dies each (Ubuntu 24.04, ROCm 7.14 TheRock ML-gfx906 apt).
Other GPUs are not a goal; the code keeps upstream's architecture guards but nothing here is tested elsewhere.

The measurements, the launch profiles, the optimiser and the power rules live in the companion repository
**https://github.com/exabit-io/llama.cpp-gfx906-tuning** (referred to below as "the tuning guide"; on the box it is
`/root/llama.cpp-benchmarking`).

Branch `gfx906` is the product. Branch `master` mirrors upstream and is only the merge source.

## Status of the branch (2026-09-09)

**Validated, not promoted.** The fork's b10912 state repacks Q8_0 weights at upload by default (`q8_repack/`; `--no-repack`,
`llama-bench -nr 1`, turns it off). With the repack: prefill +21% on four dies / +28% on one die and decode +15–20% at 24–32
slots over the production build, but 1–16 slots run a repacked kernel that bypasses the series' fast path (1–2 streams
collapse, 9–16 slots fall into a cliff). With `--no-repack`: parity with production except the single stream (−5%). Either
way the MTP gate is failed (single user, draft 3, 32K: −5 to −7%, verify-step cost). Promotion gates and the measurements:
tuning guide `NEXT-STEPS.md` "Promotion gates" and `reports/2026-09-08-review-followup.md`.

**Branch `s1b-a`** (candidate 1 of the fast path on the repacked layout; head = the `a3` form, tags `s1b-a`, `s1b-a2` are
the earlier forms): the repacked narrow-batch mat-vec instantiated through 16 columns for Q8_0 with width-dependent launch
bounds. Measured: 12/16 rows at parity with production, 17 rows +15%, 24/32 rows +15/+20%, one die 12/16 rows +11/+9%,
prefill +20%, perplexity 5.6173, `test-backend-ops` clean, server level +1–3% at 8 clients and +5.5% at 16. The single
stream is still −5%: candidate 2 (next) ports the production one-column whole-block load (commit 9931a712b) to the
two-plane layout. When both pass the gates, `s1b-a` merges into `gfx906` and the build is promoted.

**Reference perplexity** for Qwen3.8-27B Q8_0 at 16K/6 chunks is **5.62** on upstream since 2026-09-06 (5.5969 on the
b10254/b10288 production lineage); the move is upstream's (`-funsafe-math-optimizations` removed 2026-08-12, then the GDN
norm eps inside the root 2026-09-06; tuning guide `reports/2026-09-08-ppl-bisect.md`). Never read the 0.4% as a regression.

**Qwen3.8-Flash-Next** (`qwen4exp`, 512 experts) loads on this branch with `LLAMA_PLE_SHARD=1` (27.7–28.1 GiB per die,
UD-Q4_K_XL): 365 tok/s prefill, ~42 tok/s steady decode on four dies after a two-sample warm-up.

**After-load warm-up:** the first 100–300 tokens of every process, and the first cells of every new batch shape, run
15–55 tok/s before settling; it tracks the repack default and no fork commit was found responsible. Prewarm 256 tokens
per batch shape after load (the tuning guide's `settings/launch.sh` will do it).

**Not on GitHub:** branch `s1-upstream` (the MMQ config table as one patch against upstream master, prepared for an
upstream PR; the commit is Marko Tombak's and goes out only with his agreement — tuning guide `patches/upstream-S1/`).

## Build and run

```sh
scripts/gfx906/build.sh /opt/llama.cpp-gfx906        # cmake flags every measurement used
set -a; . scripts/gfx906/env.sh; set +a                # RCCL topology, custom allreduce with the 4-row gate
LD_LIBRARY_PATH=/opt/llama.cpp-gfx906/lib /opt/llama.cpp-gfx906/bin/llama-server -m model.gguf \
  --device rocm0,rocm1,rocm2,rocm3 -sm tensor -fa on -b 2048 -ub 2048 -np 16 -c 524288
```

The binaries carry no rpath: always set `LD_LIBRARY_PATH` to the install's `lib/`. Profiles, the optimiser and the power rules
are in the tuning guide (`settings/launch.sh`, `settings/gfx906.env`, `optimize/`).

```sh
# Qwen3.8-27B Q8_0 on current upstream), greedy + KL at 64-token batches against the current production, llama-bench
# pp2048/tg128 on tp4 and one die, batched-bench 1..17,24,32 slots, then the three promotion gates
#   -> tuning guide tools/gfx906-master-validate.sh, tools/s1b-test.sh (A0 + E), NEXT-STEPS.md "Promotion gates"
```

Also fetch the mx-llama.cpp fork (`git fetch mxxm --tags`) and merge its newer tags when they carry gfx906 work; its features
are documented in `FEATURES.md`, and its author rebases onto upstream every few days.
