# llama.cpp for gfx906 (Radeon Pro Vega II / MI50 class, wave64, no MFMA)

This repository is a gfx906-only llama.cpp: upstream master plus everything known to make the four-die Vega 20 boxes fast,
maintained for a fleet of 2019 Mac Pro nodes with four gfx906 dies each (Ubuntu 24.04, ROCm 7.14 TheRock ML-gfx906 apt).
Other GPUs are not a goal; the code keeps upstream's architecture guards but nothing here is tested elsewhere.

The measurements, the launch profiles, the optimiser and the power rules live in the companion repository
**https://github.com/exabit-io/llama.cpp-gfx906-tuning** (referred to below as "the tuning guide"; on the box it is
`/root/llama.cpp-benchmarking`).

Branch `gfx906` is the product. Branch `master` mirrors upstream and is only the merge source.

**Qwen3.8-Flash-Next** (`qwen4exp`, 512 experts) loads on this branch with `LLAMA_PLE_SHARD=1` (27.7–28.1 GiB per die,
UD-Q4_K_XL): 365 tok/s prefill, ~42 tok/s steady decode on four dies after a two-sample warm-up.

**After-load warm-up:** the first 100–300 tokens of every process, and the first cells of every new batch shape, run
15–55 tok/s before settling; it tracks the repack default and no fork commit was found responsible. Prewarm 256 tokens
per batch shape after load.

## Build and run

```sh
scripts/gfx906/build.sh /opt/llama.cpp-gfx906        # cmake flags every measurement used
set -a; . scripts/gfx906/env.sh; set +a                # RCCL topology, custom allreduce with the 4-row gate
LD_LIBRARY_PATH=/opt/llama.cpp-gfx906/lib /opt/llama.cpp-gfx906/bin/llama-server -m model.gguf \
  --device rocm0,rocm1,rocm2,rocm3 -sm tensor -fa on -b 2048 -ub 2048 -np 16 -c 524288
```

The binaries carry no rpath: always set `LD_LIBRARY_PATH` to the install's `lib/`. Profiles, the optimiser and the power rules
are in the tuning guide (`settings/launch.sh`, `settings/gfx906.env`, `optimize/`).
